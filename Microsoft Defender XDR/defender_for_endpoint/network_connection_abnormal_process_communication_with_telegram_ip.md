# Abnormal Process Communication with Telegram IP

## Description
This rule aims to identify potentially suspicious network communication between processes running on endpoints and IP addresses belonging to Telegram infrastructure. Telegram is a legitimate messaging platform, but its infrastructure and Bot API can also be abused by malware and other unauthorized tooling as a communication channel, allowing compromised systems to exchange information with attacker-controlled bots or services while blending into traffic associated with a widely used platform. The detection focuses on communication initiated by processes that are not expected Telegram clients or commonly used web browsers, increasing the likelihood of identifying custom applications, scripts, malware, or other unusual executables communicating directly with Telegram infrastructure. To determine whether an IP address belongs to Telegram, the rule uses the CIDR ranges officially provided by Telegram.

## Blind Spots

- Whitelisted processes can be injected and may communicate with Telegram, producing no results with this query
- A potential change of the URL or the URL content structure provided by Telegram will result in the query producing no results

## Common False Positives

- Legitimate applications that integrate with the Telegram API or Telegram Bot API for notifications, monitoring, automation, or other business purposes
- Portable, renamed, or alternative Telegram clients whose executable or product information does not match the expected application identifiers
- Browsers that were not included in the whitelists portion of the query

## Investigation Guidelines

- Review the initiating process name, file path, command line, signer information, hash, parent process, and process creation context to determine whether the executable is expected on the affected endpoint
- Investigate the process tree surrounding the initiating process and identify whether it was launched by scripting engines, command interpreters, document applications, temporary files, user-writable directories, or other unusual parent processes
- Review additional network activity generated by the same process and endpoint to identify communication with other external destinations, unusual connection patterns, or infrastructure associated with suspicious activity
- Determine whether the initiating process or its hash has been observed on other endpoints and whether communication with Telegram infrastructure is common for that application within the environment
- Investigate additional endpoint alerts and process activity around the time of the connection for evidence of suspicious execution, persistence, credential access, payload execution, or other activity that could indicate compromise
- Determine whether the application has a legitimate operational requirement to communicate with Telegram services

## Query

```KQL
// Official List of Telegram CIDRs
let TelegramCIDRs =
    externaldata(CIDR:string)
    [@"https://core.telegram.org/resources/cidr.txt"]
    with (format="txt");
// IPv4 IPs from the list.
let TelegramIPv4Ranges =
    toscalar(
        TelegramCIDRs
        | where CIDR contains "."
        | summarize make_set(CIDR)
    );
// IPv6 IPs from the list.
let TelegramIPv6Ranges =
    toscalar(
        TelegramCIDRs
        | where CIDR contains ":"
        | summarize make_set(CIDR)
    );
DeviceNetworkEvents
| where isnotempty(InitiatingProcessFileName)
| where ipv4_is_in_any_range(RemoteIP, TelegramIPv4Ranges)
    or ipv6_is_in_any_range(RemoteIP, TelegramIPv6Ranges)
// Exclude any missing browser file name along with its respective product name.
// Telegram Desktop application is also excluded, since it is expected to communicate with Telegram IPs
| where not (InitiatingProcessVersionInfoProductName in ("Firefox", "Google Chrome", "Brave Browser", "Opera Internet Browser", "Telegram Desktop")
    and InitiatingProcessFileName in ("chrome.exe", "brave.exe", "firefox.exe", "opera.exe", "telegram.exe"))
| summarize arg_min(Timestamp, *), RemoteUrls = make_set(RemoteUrl) by DeviceName, InitiatingProcessFileName
| project-away RemoteUrl  //optional
```
